# ALFWorld：小更新是方向不对，还是被 BF16 舍入了？

前一轮在 Qwen3.5-27B 的最后一个解码器层做了一次 LoRA 更新。用 `1e-6` 或 `1e-5` 时，14 个固定状态的动作分差在 BF16 下都没变。这里不重训，拿同样的三份更新后权重重算，区分“没推动正确动作”和“推动了，但读数太粗”。

## 怎么测

在同一个决策位置，比较正确动作和替代动作第一个不同 token 的分数。比如 `cool` 和 `move`，我们看 `logit(cool) - logit(move)`。分差往上，表示模型相对更偏向 `cool`；但分差仍小于零时，`move` 仍在前面。这不是整条命令的概率。

固定 14 个前缀和同一个更新前检查点：4 个参与更新的冷却状态、4 个未参与更新的同类状态、2 个原来已选对的对照状态、4 个开发对照状态。三档都来自同一起点上的单次更新。对每份权重测三种精度：

1. 原 BF16 路径。
2. 仍用原来的 BF16 隐藏表示，只用 FP32 重算两个候选 token 的输出分数。
3. 从同一份倒数第二层输出出发，用 FP32 重算最后一层（含 LoRA）、归一化和两个候选分数。前面的层和基座权重不变。

每种精度都和**自己在更新前**的分差比较。原 BF16 的 70 次检查全部复现；只提高输出层精度时，把分数转回 BF16 也逐项复现了原分数。重复加载起点，三种读数的分差都完全一致。

## 看到了什么

最后一层和输出层都用 FP32 时，参与更新和未参与更新的冷却状态结果如下。表中增加数按分差变化超过 `1e-5` 计。

| 学习率 | 参与更新的 4 个状态：分差上升数；平均变化 | 未参与更新的 4 个同类状态：分差上升数；平均变化 |
| --- | ---: | ---: |
| `1e-6` | 4/4；+0.000080 | 4/4；+0.000073 |
| `1e-5` | 4/4；+0.000825 | 4/4；+0.000746 |
| `1e-4` | 4/4；+0.009949 | 4/4；+0.009043 |

只提高输出层精度能看见 BF16 最终分数舍掉的一部分变化，但方向并不一致。例如同一个冷却状态在 `1e-4` 下，原始 BF16 的分差变化是 **−0.125**，只提高输出层精度后是 **−0.00180**，最后一层也改用 FP32 后是 **+0.00952**。只把算好的 BF16 分数转成 FP32，不能找回已经舍掉的变化。

## 学到什么

对这 8 个冷却状态和这三次单步更新，提高末层计算精度后，更新都提高了正确 token 相对替代 token 的分数。原始 BF16 的零变化不足以判定更新无效；只查输出层也不能说明全部现象来自最后一次舍入。

但三档都没有让这 8 个状态里的正确 token 超过替代 token。本次只重算固定前缀的分数，没有重新训练或跑闭环任务。因此还不能据此选择生产学习率，或声称 ALFWorld 成功率会提高。

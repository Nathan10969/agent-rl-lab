# 多轮 GRPO：真实模型冒烟

## 目的

用一组真实积木交互检查“多轮采样 → 整局奖励 → 组内优势 → 动作 token 损失 → LoRA 更新 → 重新加载”是否接通。冒烟不是性能实验，不能据此判断模型是否提升。

## 配置

- 模型：Qwen2.5-0.5B-Instruct，从本项目多轮 SFT adapter 出发，仅更新 LoRA。
- 数据：冻结训练集中的 `bw-v1-train-0346`；一题采样 8 局，每局最多 6 个动作。
- 奖励：步数限制内达成目标为 1，否则为 0；中途非法动作可以根据反馈纠正。
- 算法：组内总体标准差加 `1e-4` 计算整局优势；每条轨迹的模型动作 token 先平均，再对 8 条轨迹平均；一组数据至多更新一次。
- 资源：MPS；按 128 的倍数左侧补齐每轮前文；逐回合反向传播，避免保留整局的所有计算图。

## 本次观察

- 初次冒烟后补充记录停止原因、配置指纹和更细的内存阶段检查；在新目录以同种子重新运行，奖励、优势、损失和梯度范数一致。以下记录的是补强后的第二次运行。
- 8 局奖励：`[1, 1, 0, 0, 0, 0, 0, 1]`；成功局优势约 `+1.291`，失败局约 `-0.774`。
- 采样与重算的逐 token log 概率最大差 `7.87e-6`；累计梯度裁剪前范数 `2.401`；执行了一次优化器更新，336 个 LoRA 张量发生变化。
- 冻结参数的对象及版本未变，并抽查了两个冻结参数各 64 个元素；这不是对全部基础模型权重的逐字节比较。保存 adapter 后重加载，检查的第一回合 token log 概率最大差为 0。
- 采样到的 MPS driver 内存最大约 `5.071 GiB`；阶段后读取的 swap 为 `2.739 GiB`。阶段采样不代表对单次操作瞬时峰值的硬限制。
- 8 条轨迹均再次用模拟器重放，逐轮消息前文、奖励、token 与旧概率长度及组内优势核对一致。
- 44 个动作回合全部由模型生成的结束符停止；整局记录目标完成或步数用尽，未把长度截断记为主动结束。

## 限制与下一步

这个 smoke 只有一道题、一组轨迹和一次更新，没有比较训练前后独立评测成绩。采样时关闭 dropout，初次更新时 ratio 接近 1，不能声称 clip 已经发挥实际限制作用。

当前是每局一个组内优势，中途错误也可能跟随成功轨迹获得正优势。后续按路线分别加入逐步奖励和 reward-to-go、价值函数及每步优势，并与基础多轮 GRPO 做对照。新的 adapter 只保存权重，不包含优化器或随机数状态，不能精确续训。

代码入口：`grpo/train_multiturn_grpo.py`。实验的原始轨迹、模型权重和本机数据保留在忽略的输出目录，不放入公开仓库。

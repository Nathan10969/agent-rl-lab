# 积木 DAPO：从四个机制到小规模冒烟测试

## 代码做什么

这是一份面向 Blocksworld 的教学实现，不是论文的模型规模、任务、框架或实验复现。旧的 `train_grpo.py` 和已有实验结果没有修改。入口是 [`train_dapo.py`](../../grpo/train_dapo.py)，用固定 SFT step 378 adapter、训练集及模拟器 0/1 成功判定。

- [`dapo_core.py`](../../grpo/dapo_core.py)：非对称 clip（默认下界 0.8、上界 1.28）、有效 token 的总体平均、动态补采以及线性软长度惩罚。
- [`dapo_update.py`](../../grpo/dapo_update.py)：在采样结束且更新前计算并固定旧 log 概率，同一批上可多次更新；统计每次概率比范围与目标项实际被裁剪的 token 比例。
- `train_dapo.py`：只从 train 抽题；用原始 0/1 成功标记筛掉全对／全错组，补采到目标组数或预算耗尽。有对有错的组若因截断 mask 或惩罚后优势全部为零而没有可训练信号，也会筛除并记录 `no_train_signal`。每个答案的总奖励是成功分加长度惩罚，组内标准化计算优势；没有 EOS 的截断答案不参与 loss，但它的奖励仍参与该组其他答案的优势计算。长度包括结束符。这些明确的实现选择不是对截断问题的唯一处理方式。
- 默认不加 KL；这与我们原 GRPO 试跑相同，不能算此次新增差异。参数取值仅用于教学，不是调参后的推荐值。

输出必须使用不存在的新目录。预算内没有凑够组时不执行该批更新，保留不完整记录并退出。每完成一批就先存该批 adapter，以免后续补采失败时丢失已完成的更新；最终也会保存 adapter。**这些存档不包含优化器及随机状态，因此当前 DAPO 入口不支持精确续训**。权重、原始结果和数据留在本地，Git 中的摘要和哈希不等于备份。

## 手算与小模型测试

自动测试覆盖非对称 clip 的正负优势及梯度、全对／全错筛选与补采上限、不同长度答案的 token 加权、长度惩罚、截断 mask 和同批多次更新时旧概率不变。

此外，测试用手工构造的两个计划、真实积木模拟器、极小随机 Qwen 与 LoRA 连通打分到参数更新。手工答案并非这个随机模型实际采样得到，故不能充当真实模型 rollout 测试。

## Qwen2.5-0.5B MPS 冒烟测试

本机运行 1 批：每题 2 个答案、目标 1 个有效组、最多尝试 4 题、同一批更新 2 次、上限 160 token、软惩罚区间 20 token、seed 0。目标是检查链路，而不是比较模型成绩。

- 尝试 4 题：2 组全错、1 组全对、1 组有对有错；有效组含 2 份答案共 103 个有效 token。启用 `--check-sampling-logp` 后，4 题的采样与重算 log 概率最大差为约 `9.91e-5`。
- 所有生成答案都在结束符处停止；长度为 40–58 token，没有碰到软惩罚区间。因此长度惩罚和截断处理在本次真实 rollout 中**没有触发**，它们目前由构造的测试覆盖。
- 更新前第一次计算的 token 概率比范围约为 0.999994–1.000002；第二次范围约为 0.720716–1.192458。第二次的实际裁剪比例为 `1/103`。该次最大比值低于上界 1.28，所以**并未真实触发 Clip-Higher 上裁剪**；非对称上裁剪在手算梯度测试里验证。
- 含对齐检查的采样约 8.40 秒，两次更新和逐批保存约 1.31 秒，是本次运行记录，不作为未来速度保证。没有在验证集、test、PlanBench 或泛化集上评测。
- 重复使用已有输出目录会被拒绝。原 GRPO 试跑的结果和 adapter 指纹与先前记录一致。
- 逐批保存函数的拒绝覆盖已有测试；尚未运行“第 1 批成功、第 2 批补采失败”的完整训练场景。临时目录发布针对单进程使用，不保证并发写入同一存档名时的无覆盖语义；中断可能留下 `.partial-*` 临时目录。

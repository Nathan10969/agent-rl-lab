# 单卡 A800：27B FP8 加载与多轮任务初测

## 这次想回答什么

0.5B 的练习已经归档。这次不训练，只检查：官方 [Qwen3.8-27B-FP8](https://huggingface.co/Qwen/Qwen3.8-27B-FP8) 能否在一张 A800 80GB 上生成，以及未微调模型在少量多轮题上会做什么。这里的 FP8 是 8 位浮点权重，不是 INT8；也不表示已经验证过量化训练。

模型的 66 个权重分片分别通过 SHA-256 检查，匹配官方 Hugging Face 修订 `c3a462cc3d38cf351f3b26cbd763469eeb74ef81`。环境为 PyTorch 2.11.0+cu130、vLLM 0.24.0；ALFWorld 使用 0.4.2 和 TextWorld 1.7.0。模型、数据、原始轨迹和日志不提交到公开仓库。

## 一句话生成与显存

文本模式、关闭 thinking、贪心生成、最大上下文 2,048：模型成功生成了 26 个 token，首次加载与初始化约 34.8 秒，本次生成约 4.7 秒。这是一次冒烟，不是吞吐量基准。

- vLLM 报告模型权重加载占用约 **28.03 GiB**。
- 整个生成过程每秒采样一次 GPU，观察到的峰值为 **65,105 MiB，约 63.6 GiB**；总显存为 80 GiB。此数包含推理框架按 `gpu_memory_utilization=0.8` 预留的空间，不能当作纯权重大小或瞬时绝对峰值。
- A800 没有原生 FP8 计算支持；本次 vLLM 使用 Marlin 的 FP8 **权重压缩**兼容路径。推理可以运行，不等于 LoRA 反向传播或多轮 RL 可以直接运行。

## 固定开发题：一步动作、一次反馈

共同设置：最多 20 步、temperature 0、关闭 thinking、每步最多生成 48 token，遇换行停止；每步将环境反馈放回模型上下文。服务端最大上下文为 4,096。下面都是小样本流程检查，不是正式 benchmark。

| 环境 | 选题 | 结果 |
|---|---|---|
| Blocksworld | 3 道现有 val 开发题，最短解分别为 4、6、8 步 | **3/3 成功**；30/30 次动作格式正确且合法；实际分别走了 12、10、8 步 |
| ALFWorld 首次 | `valid_seen` 字典序的 3 题，碰巧同属一个任务类型 | **0/3 成功**，均达到 20 步上限 |
| ALFWorld 补测 | `valid_seen` 按任务类型去重后选 3 题 | **0/3 成功**，均达到 20 步上限 |

两次 ALFWorld 选题有 1 道重合，所以合计是 **5 道不同题**，不是 6 道。补测覆盖观察物体、拿取并放置、清洗后放置三类；这些均是固定规则选出的极小样本，不能外推为整个 ALFWorld 的成功率。

一条失败轨迹里，模型先找到桌子并打开台灯，随后多次尝试查看物体，环境多次反馈“没有发生任何事”。仅凭这句话不能断言是命令不被识别还是执行条件不满足。当前提示只要求每轮输出一个命令，**没有提供完整的动作格式说明或示范**；20 步上限和关闭 thinking 也会影响表现。下一步应在同一批题上先对照“有无静态动作格式说明”，再考虑训练，不能把当前结果简单归因于模型能力。

多轮评测过程的显存采样峰值为 **65,035 MiB，约 63.5 GiB**，同样包含预留空间。Blocksworld 和 ALFWorld 使用的任务不同，也不能直接和之前经过 SFT 的 0.5B 成绩比较。

## 两次配置踩坑

1. 计算节点缺少与 Python 3.10 对应的开发头文件，vLLM 初始化时编译组件失败。我们在实验私有目录准备匹配版本的头文件，并通过 `CPATH` 提供给本次作业，没有修改系统环境。
2. 权重加载后，默认 FlashInfer 采样组件尝试使用缺失的 `nvcc`。本次设置 `VLLM_USE_FLASHINFER_SAMPLER=0`，切回 vLLM 提供的替代路径；随后生成成功。换机器或软件版本仍应重新验证，不能假定这些设置普遍适用。

## 复现边界与代码

`a800/` 包含模型冒烟、显存采样、多轮评测和单元测试；`blocksworld/step_env.py` 提供逐步环境。ALFWorld 仍需自行安装并准备其官方 `valid_seen` TextWorld 数据。不要把模型、数据、实验日志或运行时的私人路径提交到 GitHub。

积木题的三个原始 ID 是 `bw-v1-val-0326`、`bw-v1-val-0166` 和 `bw-v1-val-0370`。在已有并核验过的 v1 val 数据上，可用下面的命令在**新文件**中重建本次的三题输入：

```bash
python a800/build_cases.py --val data/blocksworld/v1/val.jsonl --output /path/to/new-cases.json
```

`build_cases.py` 不覆盖已有文件。原有数据生成脚本可能覆盖同名数据和 manifest；需要重新生成时，应先备份或使用独立副本。评测入口 `a800/pilot_server.py --help` 接受模型、vLLM、ALFWorld Python、数据和全新结果目录等路径；在集群上应通过 Slurm 申请计算节点后运行。首次运行和补测的 ALFWorld 选题方式不同，当前代码对应补测的“不同任务类型”规则。

在当前机器和检查范围内，Blocksworld 原有测试、逐步环境测试和 A800 工具测试合计 **52 项通过**。这不等于模型能力已经经过大规模评测，也不覆盖未来的训练兼容性。

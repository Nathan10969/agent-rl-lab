# 从完整 SFT 到第一次 GRPO

这是一份本机学习记录：先教模型输出积木计划，再让模型自己生成计划，由模拟器打分，最后比较训练前后。重点是理解训练流程；本页的数字不代表对真实机器人、其他模型或新任务的泛化能力。

## 1. 完整 SFT：先学习参考答案

使用 Qwen2.5-0.5B-Instruct 和 LoRA，在 Mac MPS 上用 float32 训练。数据来自本地 Blocksworld v1：训练集 3021 道、验证集 378 道。batch size 为 8，学习率为 0.0002，LoRA rank 16、alpha 32、dropout 0.05；1 个 epoch 共更新 378 步。

| 模型状态 | 完整 val loss |
| --- | ---: |
| SFT 前 | 0.851121 |
| step 126 | 0.092822 |
| step 252 | 0.063831 |
| step 378 | 0.056150 |

按验证 loss 在三个存档中选中 step 378。对完整 378 道 val 贪心生成时，SFT 前成功 0 道，step 378 成功 292 道。贪心生成是每次选择概率最高的下一个 token；格式正确、动作合法与目标达成分别检查，不能混为一谈。

## 2. GRPO 前：看随机采样有没有组内差异

为了观察不同存档的随机采样，每个存档在 train 和 val 各取固定的前 100 道题，每题采 8 个答案，温度 1.0。下表的“混合组”指同一题的 8 个答案中既有成功也有失败。

| 指标（train / val） | step 126 | step 252 | step 378 |
| --- | ---: | ---: | ---: |
| 随机采样成功率 | 22.2% / 21.4% | 35.5% / 33.8% | 36.9% / 39.1% |
| 有对有错的题 | 72 / 69 | 94 / 93 | 93 / 83 |
| 贪心成功题数 | 53 / 59 | 81 / 74 | 73 / 76 |

这是固定题目、一次采样设置下的诊断，不代表全部训练题。最终选择 step 378 作为第一次 GRPO 的起点；step 252 也是有依据的备选，尚未做同预算的 GRPO 对照。

## 3. 第一次 GRPO：模型自己答题并接受评分

在 step 378 的 LoRA adapter 基础上试跑 20 步，每步抽 4 道训练题，每题随机生成 8 个答案。每个答案由模拟器执行：动作全部合法且最终完成目标得 1，否则得 0；不额外奖励短计划。

- 优势：每组用 `(奖励 - 组平均) / (总体标准差 + 1e-4)`；温度 1.0；学习率 1e-5；随机种子 0。
- 每个答案先在有效 token 上求平均，再对答案求平均；每批只更新一次，KL 系数为 0。该配置中 ratio 在求梯度处为 1，clip 不触发，因此这是**简化的组优势策略梯度试跑**，尚未实验旧数据多次更新时的 clip 行为。
- 总共生成 640 个答案，其中 363 个成功；80 组中 65 组有对有错、8 组全对、7 组全错。各步题目不同、模型也在变化，所以 363/640 不能直接和上表固定题目的采样成功率比较。
- 各步记录的 MPS driver 读数为 2.91–4.24 GiB；它们是采样时点读数，不是全程峰值，也不能据此判断系统 swap。
- 已保存 step 10 和 step 20 的 adapter；没有保存优化器、随机数状态和数据游标，因此不能从这些存档精确无损续训。日志只抽查了两个基础模型矩阵没有变化，不代表逐一检查了所有冻结参数。

## 4. 完整验证集：同题比较训练前后

对完整 378 道 val，使用相同的题目、batch size 2、最多生成 160 个 token 和贪心解码设置。SFT 一侧使用先前保存的逐题答案，并用当前模拟器重新判分；GRPO step 20 重新生成。逐题按 id 配对。

| 指标 | SFT step 378 | GRPO step 20 |
| --- | ---: | ---: |
| 格式正确 | 367 / 378 | 367 / 378 |
| 动作均合法 | 301 / 378 | 331 / 378 |
| 最终成功 | 292 / 378（77.2%） | 318 / 378（84.1%） |

51 道原来错、现在对；25 道原来对、现在错，因此净增加 26 道，即约 6.9 个百分点。前 100 题之外的 278 题从 216 道成功变为 230 道成功。完整评测用时 479.7 秒。

**结论边界：**这是固定 val、贪心生成、一次 GRPO 随机种子下的观察。该验证集曾参与 SFT checkpoint 选择，也用于开发；不能把结果当成独立最终测试或证明随机采样及其他环境同样提升。尚未做 test、6–7 块泛化题或 PlanBench 的训练后评测。

## 5. 真实案例：变对和变错

以下是验证集的示例，用于理解错误；不要把这些题加入训练。

**原来错、现在对：`bw-v1-val-0083`。** 初始 A 在 C 上、D 在 E 上，B 单独在桌上；目标是 C 在 B 上、D 在 C 上。SFT 的动作开头为：

```text
unstack(A, C)
putdown(A)
unstack(D, E)
stack(D, C)
pickup(C)       # 不合法：刚把 D 放在 C 上
stack(C, B)
```

GRPO 后的输出先将 D 放到桌上，移动 C 到 B 上，再将 D 放到 C 上：

```text
unstack(A, C)
putdown(A)
unstack(D, E)
putdown(D)
pickup(C)
stack(C, B)
pickup(D)
stack(D, C)
```

模拟器判定成功，但这份计划用了 8 步，参考最短计划是 6 步。当前奖励只判断成功与否，所以做对但绕路仍得 1 分。单个案例不能证明模型内部的推理过程。

**原来对、现在错：`bw-v1-val-0110`。** SFT 生成的计划通过模拟器；GRPO 后的计划末尾出现 `stack(D,桌上)`，不符合动作格式，因而判分失败。它提醒我们总成功数提高并不等于每道题都改进。

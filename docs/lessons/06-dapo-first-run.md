# 积木 DAPO：20 批训练与完整验证集对照

## 做了什么

从之前相同的 Qwen2.5-0.5B-Instruct + SFT step 378 adapter 出发，用积木训练集训练 20 批，再对固定 378 题 val 贪心生成一次并用同一模拟器判分。只使用训练集补采和更新；没有用 test、6–7 块泛化集或 PlanBench。实现细节与限制见[第一版记录](05-dapo-first-implementation.md)。

设置：每题 8 个答案；每批收集 4 个有信号的题组，每批最多尝试 20 题；每批更新 2 次，学习率 1e-5，seed 0，MPS float32。使用动态补采、上下界 0.8 / 1.28、token 平均、接近 160 token 上限的 20 token 软惩罚区间及截断 mask；不使用 KL。

实际完成 20 批、40 次优化器更新；尝试 117 道题，生成 936 份答案，共 44,605 个生成 token（含结束符）；筛出 80 个混合组、5 个全错组、32 个全对组，无 `no_train_signal` 组。没有答案被截断或进入长度惩罚区间，所以**该机制没有在这轮实际触发**。跨两次更新共统计 59,462 个有效 token 更新事件，其中 35 个触发裁剪；记录未区分上下界，不能据此声称 Clip-Higher 上界实际触发。

各批记录的采样及更新耗时之和约 768.8 秒；这不是整个进程的端到端耗时。系统开始前已有约 2.9 GiB swap，训练与评测前后观测值没有增加；这不证明全过程的 swap 峰值为零。每批保存 adapter，但不支持精确续训。

## 完整 val：同题比较

沿用之前每批 2 题、最多 160 个新 token 的贪心生成；重新核对验证集 ID、文件指纹和旧结果的模拟器判分。SFT 和 GRPO 使用以前保存的逐题输出；DAPO 本次重新生成。评测耗时 443.6 秒。

| 指标 | SFT | 之前 GRPO | 本次 DAPO |
| --- | ---: | ---: | ---: |
| 格式正确 | 367 / 378 | 367 / 378 | 373 / 378 |
| 动作均合法 | 301 / 378 | 331 / 378 | 336 / 378 |
| 最终成功 | 292 / 378（77.2%） | 318 / 378（84.1%） | 321 / 378（84.9%） |

与 SFT 比，47 题由错变对、18 题由对变错，净增 29 题。与之前 GRPO 比，23 题由错变对、20 题由对变错，净增 3 题（约 0.8 个百分点）。逐题重判和汇总核对均通过。

**不能据此断言 DAPO 优于 GRPO。** 之前 GRPO 是 20 批、20 次更新、生成 640 份答案（30,567 个生成 token）；本次 DAPO 是 20 批、40 次更新、生成 936 份答案（44,605 个生成 token），还同时改变了多项机制，训练机会和预算并不相同。两次均各自只有一次 seed 0 运行，val 还曾用于选择 SFT checkpoint，因此不等于独立测试集结论。训练中不同题目、不同模型状态下的成功率也不能直接当作固定题集上的提升。

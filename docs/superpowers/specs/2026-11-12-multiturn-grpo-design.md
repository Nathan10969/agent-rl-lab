# 多轮 GRPO 最小基线设计

## 目的和范围

把多轮积木环境接到基础 GRPO：同一道训练题采集多条完整轨迹，按最终任务结果给每条轨迹打分，用组内优势更新 LoRA。先跑小规模冒烟验证链路；不以一次试跑判断模型是否变强，不运行长时间训练。

后续必须在仓库实现并单独对照逐步奖励与 reward-to-go、价值函数和每步优势；它们不属于本次基础基线，不把它们错误描述为已经实现。

## 数据与采样

- 使用冻结的 Blocksworld 训练集和现有多轮环境，验证训练集指纹；验证集、测试集及保留评测题不作为训练题。
- 从已有多轮 SFT adapter 出发，冻结基础模型，只训练 LoRA。每轮参数更新前保持策略固定，按同一题目采样一组轨迹；首个冒烟使用 1 题、8 条轨迹、每条最多 6 个动作。
- 每步动作及环境反馈依次加入消息历史；采样时保存当轮精确前文 token、模型生成 token 和采样分布下逐 token 的旧 log 概率。保存终止原因、环境反馈、动作是否合法及奖励。环境的反馈不生成策略损失。
- 对换行、结束符和环境实际接收文本明确记录：使用生成时的原始 token 算本轮概率，不能假设经解码、裁切并套模板后的历史与原始输出总是逐 token 相同。
- 目标在步数限制内完成为 1，否则为 0；中途非法动作返回错误反馈并允许继续，最终成功仍为 1。该规则与原单轮实验“全程合法才奖励”的规则不同，结果不得直接视为同一实验。

## 优势与更新

- 每道题独立计算轨迹组均值及总体标准差，复用既有 GRPO 优势定义及 epsilon；全对或全错时该组优势为零，不补采，不强行产生更新。
- 一条轨迹采用一个整局优势；每个模型生成 token 按自身采样时和当前策略条件概率计算 ratio 及裁剪目标。每条轨迹先对其全部模型动作 token 求平均，再对轨迹求平均；分轮/分小批反传必须与此归一化等价。
- 用与采样相同的条件前文、采样温度及 token 重新计算当前 log 概率，环境消息及模板前缀仅作输入不计损失；已生成的回合结束符按实际行为明确计入。参数更新前检查采样与重算概率偏差并在超限时停止。
- 初版每组数据只更新一次，clip 不应被宣传为在初次 ratio=1 时有效限制更新。关闭 dropout、设置梯度裁剪，保存梯度范数及是否有有效组。

## 安全和验收

- 新建独立输出目录且拒绝覆盖，原 adapter 与既有实验保持不变；记录模型、tokenizer、模板、数据、代码和配置指纹、轨迹及结果。不得将数据、权重或原始输出自动提交公开仓库。
- 先做可手算的单元测试：组内优势、轨迹回放、跨轮动作 mask、生成 token 概率对齐、跨轮损失归一化、终止与全零优势；再做小规模真实模型冒烟。
- 冒烟核对完整轨迹、奖励和优势、旧/新概率对齐、仅 LoRA 参数更新、基座参数未改变，以及保存后重加载的可比性；记录 MPS/系统内存并设置保护。若全组奖励相同则如实记录并跳过更新，不把它算作更新成功。
- 冒烟只证明实现和链路，不证明训练提升；后续训练预算、检查点选择和独立评估在启动前另行确定。

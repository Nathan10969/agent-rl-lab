# SFT 与 MPS 内存排查：学习记录设计

## 目标

在现有学习仓库中保存第一轮 Blocksworld SFT 和 MPS 内存排查的过程，让读者能够按“现象 → 如何检查 → 改了什么 → 结果 → 还不知道什么”的顺序理解，而不是只看到最终代码。

## 组织方式

- README 更新当前进度，用简短链接指向单独的 SFT / MPS 学习记录。
- 学习记录记录任务、两次试运行设置和结果、内存探针对照、可复现入口与后续问题。
- 检查现有 `sft/` 代码后提交相关脚本；训练数据、模型权重、输出与 adapter 继续遵循 `.gitignore`，不自动上传。
- 所有数字基于本机结果和日志，写明保存位置和文件指纹；不把忽略的文件描述成已经上传。

## 真实性与安全边界

- 区分系统的进程 footprint、系统级 swap 和步骤结束时的 MPS driver 采样；不将其视为同一项指标或全程峰值。
- 固定长度与清缓存同时改变；报告观测结果，不声称已证明唯一底层机制、完全排除泄漏、全程无 swap，或确定结果差异的原因。
- 保留 32 道验证样本的规模限制；不把格式通过等同于规划正确或正确停止。
- 明确单轮 mask 的适用范围；原训练脚本的固定输出目录可覆盖现有成果，未做防护前不得建议直接重复运行。
- 不修改他人尚在工作的文件，不启动完整训练；检查结果与实际执行范围分开报告。

## 验证

核对两次原始结果、探针日志和其摘要指纹；检查代码与文档是否对应，并运行不覆盖既有数据的相关测试。确认提交作者与远端目标，再按授权提交。

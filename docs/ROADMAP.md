# 任务规划训练实践路线

记录日期：2026-10-28。按验收推进，不承诺固定月份完成。以下是学习安排，不是已经完成的实验。

## 第一条主线与边界

从 Blocksworld 文本任务规划入门，再评估是否迁移到 ALFWorld 多轮交互。最初只涉及离散状态和动作，不涉及真实机械臂、视觉输入或连续控制。

统一的是学习主题和训练接口，不保证模型、checkpoint、数据集能直接从头沿用到尾。Blocksworld 上的改进不能直接外推为 ALFWorld 或真实机器人上的改进。

### 当前学习顺序（2026-11-09 用户确认）

先从确定性的多轮积木交互开始，一步动作、一次反馈，暂时不训练；再依次学习多轮训练数据与 loss mask、多轮 RL、基于验证成功轨迹的有限自我训练，最后在遮挡或外部变化环境中学习记忆。下面的历史章节编号保留作资料索引；其中 2c 的有限自我训练排在多轮 RL 之后，不按编号提前执行。有限自我训练是 RSI 入门，不等于开放式递归自我改进。

## 0. 先看懂一条任务与验证器

顺序：初始状态 → 目标 → 合法动作 → 状态变化 → 是否成功。

之后才逐步写模拟器、参考求解器和生成器，不以“约 100 行”为验收标准。

验收：

- 能手工判断合法、非法及最终目标是否满足。
- 模拟器有状态不变量、非法动作和终局判分测试。
- 小状态空间下穷举，核对参考求解器输出的计划可重放且成功。
- 训练、验证、测试按任务去重并冻结测试集合；不靠不同 seed 假定无重复。
- 去重同时考虑积木改名和跨写法的语义等价：例如 3 块积木时“A 在 B 上、B 在 C 上”已经隐含“C 在桌上”，与写全的目标是同一道题。按 `blocksworld/` 当前规则复核：3–5 块积木中，写全目标的题 2,353 道，真正的部分目标题 1,717 道，合计 4,070 道语义不同的题。
- PlanBench 等外部评测先对齐规则，再标记与训练题同构的题，完整结果和去重后的结果都报告。
- 先用 BFS（广度优先搜索：按动作数从少到多寻找解）检查小题可解性与最短步数，控制状态空间规模。

## 1. SFT：先模仿正确计划

输入：状态、目标和动作说明。输出：一条正确动作序列。

逐个学习：一条样本 → user / assistant → chat template → token → labels / loss mask → LoRA → 保存和加载 → 固定评测。

验收：

- 能解释一条样本中哪些 token 参与 loss，结束符是否参与。
- 能区分生成格式正确、每步动作合法和最后任务成功。
- 保存再加载后的确定性输出在受控设置下保持一致。
- 记录未微调模型和 SFT 模型在同一固定集合上的结果。
- 跨本地与云端时核对 tokenizer、模板、精度和推理设置，再比较 token log-prob；不要求不同后端逐位相同。

模型选择：0.5B 用于流程试运行，1.5B 是独立候选实验线；先测能力与资源，再确定 base / instruct 和训练起点。

## 2a. GRPO：自己尝试，让验证器判分

同一道题采多份计划，每份计划由模拟器检查。在最初的二元奖励中，全部动作合法且最终达成目标记 1，否则记 0；另行记录错误类型与步数，不偷偷混进奖励。

逐个学习：组采样 → 组内优势 → token log-prob → 新旧概率比 → clip → 是否使用 KL 项及其系数。

验收：

- 能手算一组奖励和优势，理解全 0、全 1 组为什么没有组内区分信号。
- 记录成功率、全零/全一组比例、有效组比例、生成 token 数和采样成本。
- 先核对起点模型是否偶尔能成功；若大量组无信号，检查任务难度、奖励和 SFT 起点，而不是无限补采。
- 固定评测和生成预算，比较起点、SFT、直接 GRPO、SFT 后 GRPO；仅在预算允许时运行全部对照。

## 2b. DAPO：从 GRPO 基线逐项改动

DAPO 与 GRPO 密切相关，学习上放在 GRPO 后面。不要把“下一代”当作严格分类，也不要假定 DAPO 在所有任务上更好。

按原论文核对四个机制：

1. Clip-Higher：拆开上下裁剪范围，提高上界，缓解探索过早收缩。
2. Dynamic Sampling：筛除组内奖励无差异的题组并补采，不会凭空创造正确答案。
3. Token-level policy-gradient loss：改变不同长度回答的 loss 汇总权重。
4. Overlong reward shaping：处理接近生成长度上限的回答与截断造成的奖励噪声。

另记原 DAPO 配方移除了 reference-policy KL 项；这与新旧策略概率比、clip 不是同一件事。如果起始 GRPO 本就没有 KL 项，必须照实写明，不能算作新增差异。

验收：

- 每次只改一项，解释它针对的问题；框架版本与实际配置逐项留档。
- 同时记录训练更新数、总生成 token、补采次数和耗时，不能仅比较 epoch。
- 短计划上无明显收益是可记录的结果，不人为拉长输出来制造优势。
- 将“教学消融”与“原论文完整复现”区分；不假定调一个 loss_type 就完成 DAPO。

## 2c. 有限自我训练：通向 RSI 的小实验

先做 ReST-EM 风格的有限循环：固定训练题池 → 当前模型采样 → 模拟器筛选成功计划 → SFT → 独立评测 → 再循环。

这可以研究自生成解答的迭代训练，但不等于已经实现开放式 Recursive Self-Improvement。STaR 还包含给定正确答案重新生成解释的步骤，不与简单拒绝采样完全等同。

验收：

- 留存每轮采样策略、样本来源、通过率、去重和采样预算。
- 对照固定数据 SFT、迭代筛选 SFT 和 GRPO；不能仅凭二者分数差就断言差异全来自失败样本的负信号。
- 若要分析失败样本作用，进一步控制训练起点、样本、采样预算、成功样本权重、更新次数及其他目标差异。
- 全部通过验证也不保证数据多样性或泛化，需监测退化和重复。

可选扩展：模型提出初始状态与目标，独立求解器检查合法性、可解性和最短步数。可解不等于对当前模型难，也不等于有学习价值；训练题筛选不访问固定测试题。这是自生成课程的教学实验，不称为完整复现 Absolute Zero。

## 3. 多轮 agent：每走一步就观察一次

先在积木环境中从“一次输出完整计划”切换到“动作 → 环境观察 → 下一个动作”，看懂轨迹格式和环境 token 的 loss mask，再评估 ALFWorld 的安装和模型能力。

积木环境的闭环版分四个小阶段，每次只加一项。这样表现变差时，能知道是哪一项造成的（2026-10-28 用户与 Codex、CC 对齐）：

1. 确定性多轮：每走一步，环境返回执行结果和新状态；非法动作返回原因，状态不变。
2. 动作可能失败：例如抓取按固定概率失败，模型要看到失败并重新规划。失败概率与随机 seed 固定并留档。
3. 遮挡：模型看不到完整状态，例如只看得到每摞最上面一块。
4. 外部移动物体：环境在模型看不到时移动积木，用来研究旧记忆什么时候失效。看不见不等于已被移动；信息不足时，模型可能需要同时保留几种可能，再去检查。

塔会不会倒这类物理效果以后单独加。第 3、4 小阶段也是第 4 节记忆实验的环境。

多轮信用分配学习：从非法动作 −0.1、达成目标 +1 的逐步奖励和折扣 `gamma=0.9` 的 reward-to-go 入手。后续已在教学实现中加入价值预测与每步优势，分别做了固定策略诊断和联合训练对照；结果及局限见[学习记录 11–15](lessons/11-multiturn-step-value-training.md)。这些是有限预算的多轮策略梯度／actor–critic 实验，不应与标准 GRPO 或完整 DAPO 混称。多轮代码仍在本地整理，学习记录先行公开。

后续再单独研究长度惩罚，例如每走一步扣少量分，比较计划步数和最终成功率；固定环境、评测题与采样预算，避免与当前非法动作惩罚混为同一项改动。

ALFWorld 候选路线：先人工检查和重放轨迹，再做轨迹 SFT，之后用多轮 RL。AgentInstruct 的 ALFWorld 部分和 verl-agent 是待评估的资源，不预先承诺可直接加载或复现。

验收：

- 区分任务终止、步数上限截断、工具错误与训练批次截断。
- 明确所有需要学习的 assistant 回合和工具调用；环境返回不作为 policy 生成目标。
- 能完整重放轨迹，并记录成功率、交互步数、非法动作、token 数及成本。
- 先比较简单多轮 GRPO，再理解 GiGPO 的轨迹级与步骤级信用分配。
- 论文报告的成功率仅作上游参考，不写成我们的结果或必须达到的验收线。

## 4. 可学习记忆：记什么也成为动作

先建立不学习的历史窗口或结构化记忆基线，再设计写入、读取、更新、删除等明确动作及其状态转移、预算和奖励。

verl-agent 的 SimpleMemory 是历史管理起点，不是替换一个类就自动获得记忆学习。环境也不自动包含物体被外部移动等变化；若需要这种机制，必须显式实现并测试。

验收：比较无记忆、固定记忆策略和可学习记忆，控制上下文与工具预算；区分看不到物体和有证据证明旧位置失效。

## 5. RSI 扩展与应用

在前述验证可靠后，再研究自生成任务、数据筛选和记忆策略是否构成可测量的自我改进循环。每轮仍需独立固定评测、预算、基线与回退点。

材料领域保留为后续候选应用，不因更换场景就宣称已有可验证奖励或真实机器人能力。
